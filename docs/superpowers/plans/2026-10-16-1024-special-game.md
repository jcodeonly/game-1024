# 1024 스페셜 챌린지 (1024 Special Challenge) 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 점수제가 아닌 '최소 이동 횟수'로 1024를 달성하며, 매 100회 이동마다 보드가 시계방향으로 90도 회전(숫자는 정방향 유지)하는 모바일 반응형 Next.js 1024 게임 웹서비스 구축.

**Architecture:** Next.js App Router 기반의 SSR 셸과 `"use client"` 인터랙티브 게임 컴포넌트 분리. 핵심 도메인 로직은 `Tile`, `Board`, `GameEngine` 3계층 OOP 클래스로 캡슐화하여 높은 응집도와 테스트 용이성 보장.

**Tech Stack:** TypeScript, Next.js (App Router), Tailwind CSS, Vitest (단위 테스트), Firebase Hosting, Git/GitHub.

**Spec:** [docs/superpowers/specs/2026-10-16-1024-special-game-design.md](file:///c:/Users/JAEHUN/game_1024/docs/superpowers/specs/2026-10-16-1024-special-game-design.md) / [reference/design-spec.md](file:///c:/Users/JAEHUN/game_1024/reference/design-spec.md)

## Global Constraints

- 언어: TypeScript (Strict 모드, noImplicitAny)
- 프레임워크: Next.js (App Router), 서버 사이드 렌더링 위주 + 사용자 조작 컴포넌트만 유저 사이드 렌더링(`"use client"`)
- 스타일링: Tailwind CSS (다크 아케이드 테마, 모바일 최적화 반응형)
- 버전 관리: 컴포넌트/기능별 브랜치 분기(`feat/*`), 검토 후 `main` 병합 시 버전 증가 (Semantic Versioning)
- 배포: Firebase (Firebase Hosting 구성)
- 보안: API 및 비공개 로직 클라이언트 미노출
- 참고자료: `reference/` 하위 폴더에 핵심 명세 및 문서 보관

## Review Focus

1. **100턴 회전 시 타일 좌표 매핑**: `(row, col) -> (col, 3 - row)` 공식이 회전 후 모든 타일의 위치와 일치하는가?
2. **숫자 텍스트 정방향 유지**: 보드가 90°/180°/270° 회전해도 숫자 텍스트가 거꾸로 뒤집히지 않고 0° 수평을 유지하는가?
3. **무효 조작 판정**: 상하좌우 조작 시 보드에 변화가 전혀 없는 경우 이동 횟수(Moves)가 증가하거나 신규 타일이 생성되지 않는가?
4. **1024 즉시 승리 판정**: 1024 타일이 합쳐져 만들어지는 순간 즉시 `WON` 상태로 전환되고 승리 모달이 팝업되는가?
5. **모바일 스크롤 충돌 방지**: 게임 보드 영역 내에서 터치 스와이프 시 브라우저 기본 세로 스크롤이 방지(`touch-action: none`)되는가?
